# ex02_ingest_dual_write ヒント

## toBookInput

### tier1
やることは「キー名の付け替え」だけ。値そのものを加工したり計算したり
する必要はない。C#で言えば、外部DTOクラスからドメインクラスへ
プロパティ名だけ変えてコピーするコンストラクタに相当する。

### tier2
オブジェクトリテラルを1つ作って返す。`isbn`と`title`はそのまま、
`author`には`dto.author_name`を、`publishedYear`には
`dto.first_publish_year`を入れる。

### tier3
```ts
return {
  isbn: dto.isbn,
  title: dto.title,
  author: /* ここ */,
  publishedYear: /* ここ */,
};
```

## ingestBooks

### tier1
やることは大きく2段階: 「外部データを取ってきて正のストアへ確実に
保存する」→「保存できた分だけ、副本への書き込みを試す(失敗しても
致命傷にしない)」。この2段階を1つのforループの中で1件ずつ処理すると
書きやすい。正への保存が失敗したときと、副本への保存が失敗したときで
「エラーの扱い方が違う」ことが、この課題でいちばん大事な設計判断。

### tier2
`for...of`で`dtos`を1件ずつ処理する。各件で
①`toBookInput`で変換 → ②`repo.upsertByIsbn(input)`をそのままawait
(ここはtry/catchで囲まない。失敗したら関数ごと失敗してよい)→
③`analytics.insertBookRow({...})`をtry/catchで囲んでawaitする。
catchできたら`err instanceof Error ? err.message : String(err)`で
文字列化し、`analyticsFailures`配列に`{ isbn, reason }`を積む。
ループの外で`ingestedCount`(正への保存件数)を数えておく。

### tier3
```ts
const analyticsFailures: AnalyticsFailure[] = [];
let ingestedCount = 0;

for (const dto of dtos) {
  const input = toBookInput(dto);
  await repo.upsertByIsbn(input); // 失敗したらそのまま外へ
  ingestedCount += 1;

  try {
    await analytics.insertBookRow({
      isbn: input.isbn,
      title: input.title,
      author: input.author,
      batchId,
      ingestedAt: /* ここ */,
    });
  } catch (err) {
    const reason = /* err からmessageを取り出す */;
    analyticsFailures.push({ isbn: input.isbn, reason });
  }
}

return { batchId, ingestedCount, analyticsFailures };
```
