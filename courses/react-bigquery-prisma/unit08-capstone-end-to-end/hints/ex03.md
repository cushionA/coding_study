# ex03_search_endpoint ヒント

## searchBooksWithSummary

### tier1
2つの呼び出しは「失敗したときの扱い」が非対称。一覧(Prisma)が失敗したら
このエンドポイント自体に意味が無いので諦めてよい。集計(BigQuery)が
失敗しても一覧は返したいので、この呼び出しだけをtry/catchで囲む発想。

### tier2
`repo.searchByKeyword(keyword)`は普通にawaitする(囲まない)。
`analytics.countByAuthor(keyword)`はtry/catchで囲み、成功したら
`{ items, summary }`を、失敗したら`{ items, summary: null, summaryError }`を
返す。`summaryError`はcatchした値からメッセージ文字列を取り出したもの。

### tier3
```ts
const items = await repo.searchByKeyword(keyword);

try {
  const summary = /* analyticsを呼ぶ */;
  return { items, summary };
} catch (err) {
  const summaryError = /* err からmessageを取り出す */;
  return { items, summary: /* ここ */, summaryError };
}
```

## describeSearchResponse

### tier1
`response.summary`がnullかどうかで2パターンの文字列を組み立てる、それだけ。
テンプレートリテラル(`` `${...}` ``)を使うとC#の文字列補間`$"{...}"`と
同じ感覚で書ける。

### tier2
`if (response.summary === null) { ... } else { ... }`で分岐し、
それぞれ`return`で文字列を作る。必須情報(keyword・件数・degrade時は
summaryError)さえ含めれば文言は自由。

### tier3
```ts
if (response.summary === null) {
  return `検索語『${keyword}』: ${response.items.length}件ヒット(集計は失敗: ${/* ここ */})`;
}
return `検索語『${keyword}』: ${response.items.length}件ヒット(著者別集計 ${/* ここ */}件)`;
```
