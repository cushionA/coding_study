# ex01_search_input ヒント

## SearchBox

### tier1
「入力欄に今表示されている文字列」と「デバウンス後に検索として確定させる
文字列」は同じ1つの値でよい。まず前者(制御コンポーネント)を動かしてから、
「その値が変わるたびに、少し待ってから何かする」というタイマーの仕組みを
後付けする、の2段階で考えるとよい。C#の`Timer`をキー入力のたびにリセット
する処理を思い出すこと。

### tier2
`useState`で検索語のstateを持ち、`<input>`の`value`にそのstateを渡し、
`onChange`イベントで`e.target.value`をsetterに渡す(これで制御コンポーネント
になる)。次に`useEffect(() => { ... }, [state, debounceMs])`を書き、
中で`setTimeout(() => onSearch(state), debounceMs)`を仕掛ける。
useEffectのコールバックから`return () => clearTimeout(timerId)`という
クリーンアップ関数を返すと、stateが変わって次にこのuseEffectが動く直前に
前回のタイマーが自動でキャンセルされる。`<input>`にはアクセシブルな名前が
必要なので`aria-label="検索"`を付ける。

### tier3
```tsx
export function SearchBox({ onSearch, debounceMs = DEFAULT_DEBOUNCE_MS, initialQuery = "" }: SearchBoxProps) {
  const [query, setQuery] = useState(initialQuery);

  useEffect(() => {
    const timerId = setTimeout(() => {
      onSearch(/* ここ */);
    }, /* ここ */);
    return () => {
      /* クリーンアップ: timerIdを片付ける */
    };
  }, [query, debounceMs]);

  return (
    <input
      type="text"
      aria-label="検索"
      value={/* ここ */}
      onChange={(e) => /* ここ */}
    />
  );
}
```
(依存配列に`onSearch`を含めていない点は、テストで毎回新しい関数を渡す
実装だとタイマーが余分に張り直される問題を避けるための実務上の妥協。
気になる場合は`useCallback`やrefで安定化する方法を調べてみるとよい)
