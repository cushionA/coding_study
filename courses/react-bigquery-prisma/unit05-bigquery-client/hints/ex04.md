# ex04_capstone ヒント

## runQueryWithCostGuard

### tier1
このユニットで作った部品を2つ、順番につなげるだけの関数。
①「見積もる」②見積もりが大きすぎなければ「実行する」。
新しいロジックは「大きすぎるかどうかの比較」だけ。

### tier2
まず`await bq.estimateQueryBytes(opts)`で見積もりバイト数を得る。
それが`maxBytes`より大きいなら、その時点で`bq.query`を呼ばずに
`too-expensive`の結果を返して終了する(early return)。
そうでなければ`await bq.query(opts)`を呼び、`[rows]`で分割代入して
成功の結果を組み立てる。

### tier3
```ts
const scannedBytes = await bq.estimateQueryBytes(opts);
if (scannedBytes > maxBytes) {
  return { ok: false, reason: "too-expensive", scannedBytes, limitBytes: maxBytes };
}
const [rows] = await bq.query(opts);
return { ok: true, rows, scannedBytes };
```

## describeCostGuardResult

### tier1
`result.ok`で分岐して、それぞれの場合に必要な数値をテンプレート
リテラルに埋め込むだけ。TypeScriptは`result.ok`で分岐した後、
そのブロックの中では自動的にどちらの形か絞り込んでくれる
(判別共用体の型ガード)。

### tier2
`if (result.ok) { ... result.scannedBytes, result.rows.length ... }`、
`else`側では`result.scannedBytes, result.limitBytes`が使える。
文言は自由だが、テストはメッセージの中にこれらの数値が
含まれているかどうかを見ている。

### tier3
```ts
if (result.ok) {
  return `実行OK: ${result.scannedBytes}バイトスキャン、${result.rows.length}行取得`;
}
return `実行スキップ: 見積もり${result.scannedBytes}バイト > 上限${result.limitBytes}バイト`;
```
