# ex04_capstone ヒント

## BookExplorer

### tier1
「今どの段階か(読み込み中/失敗/成功)」を1つのstateで表現し、
「コンポーネントが最初に画面に出たときに1回だけ実行したい処理」を
別のフックで書く、という2つのフックの組み合わせで作る。stateの型は
すでに`BookListState`として定義されている。

### tier2
`useState<BookListState>({ status: "loading" })` で状態を持つ。
`useEffect(() => { ... }, [])` の中で `fetchBooks()` を呼び、`.then` で
成功時に `setState({ status: "success", books })`、`.catch` で失敗時に
`setState({ status: "error", message })` を呼ぶ。依存配列を空配列`[]`にすると
「マウント時に1回だけ」実行される(unit01のPromise/async-awaitの復習:
ここでは`.then`/`.catch`のメソッドチェーンで書く。useEffectのコールバック自体は
asyncにできないので、中でasync関数を呼ぶかPromiseチェーンを使う)。
表示部分は`state.status`を見て`if`文で早期returnしていくと素直に書ける。
`role="alert"`は`<p>`に直接付けられる属性。

### tier3
```tsx
export function BookExplorer({ fetchBooks }: BookExplorerProps) {
  const [state, setState] = useState<BookListState>({ status: "loading" });

  useEffect(() => {
    fetchBooks()
      .then((books) => setState({ status: "success", books }))
      .catch((err: unknown) => {
        const message = err instanceof Error ? err.message : String(err);
        setState({ status: /* ここ */, message });
      });
  }, []);

  if (state.status === "loading") return <p>{LOADING_TEXT}</p>;
  if (state.status === "error") return <p role="alert">エラー: {state.message}</p>;
  if (state.books.length === 0) return <p>{EMPTY_TEXT}</p>;
  return (
    <ul>
      {state.books.map((book) => (
        <li key={book.id}>{book.title}</li>
      ))}
    </ul>
  );
}
```
(解答では副作用のクリーンアップ用に`cancelled`フラグも使っているが、
テストを通すだけならここまでで十分。余裕があれば「アンマウント後に
setStateが呼ばれてしまう」問題をどう防ぐか調べてみるとよい)
