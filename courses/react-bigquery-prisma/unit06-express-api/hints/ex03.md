# ex03_error_layering ヒント

## errorHandler

### tier1
このハンドラの仕事は「エラーの種類を見て、返すステータスコードとメッセージを
決める」の1点だけ。すでに`ValidationError`と`NotFoundError`という2つの
「既知のエラー」型が用意されている。それ以外はすべて「想定外」として扱う。
種類を見分けるには、C#の`catch (SpecificException ex)`のように型で分岐する
発想をJSでどう書くか思い出すこと(TSの`catch`自体は型を絞れないので、この
関数の中で自分で判定する)。

### tier2
`err instanceof ValidationError`、`err instanceof NotFoundError`で順に判定する
(if文を上から並べるだけでよい)。一致したら対応するステータス
(400 / 404)で`res.status(...).json({ error: err.message })`を返す。
どちらにも一致しなければ「想定外のエラー」なので、`console.error(err)`で
ログにだけ出し(err.messageやerr.stackはレスポンスに絶対含めない)、
`res.status(500).json({ error: "internal server error" })`という決め打ちの
メッセージだけを返す。

### tier3
```ts
if (err instanceof ValidationError) {
  res.status(400).json({ error: err.message });
  return;
}
if (err instanceof NotFoundError) {
  res.status(404).json({ error: err.message });
  return;
}
console.error(err);
res.status(500).json({ error: "internal server error" });
```
