# ex02_validate_query ヒント

## validateBooksQuery

### tier1
このミドルウェアは「検証してダメなら止める、良ければ次に進む」という1本道の
分岐でできている。zodには失敗しても例外を投げず、成否をオブジェクトで教えて
くれるメソッドがある(unit02で使ったのと同じ考え方)。パイプラインを次へ進める
ための専用の関数もExpressから渡されてくる。

### tier2
`booksQuerySchema.safeParse(req.query)`の戻り値は
`{ success: true, data: ... }`か`{ success: false, error: ... }`のどちらか。
- 成功時: `res.locals.booksQuery = result.data`としてから`next()`を呼ぶ
  (`next()`を呼ばないと、この後ろに登録されたハンドラが一生呼ばれない)
- 失敗時: `next()`は呼ばずに
  `res.status(400).json({ error: "invalid query", issues: result.error.issues })`
  を返す(`result.error.issues`はzodが教えてくれる「どこがどう間違っているか」の
  配列)

### tier3
```ts
const result = booksQuerySchema.safeParse(req.query);
if (!result.success) {
  res.status(400).json({ error: "invalid query", issues: result.error.issues });
  return;
}
res.locals.booksQuery = result.data;
next();
```
