# ex02_filter_search ヒント

## searchBooksByTitle

### tier1
部分一致検索は `where` の中で、フィールド名に対して「含んでいるか」を
表す専用のキーを使う。C#のLINQなら `.Where(b => b.Title.Contains(keyword))`
に相当する発想。

### tier2
`where: { title: { contains: keyword } }` の形。`title` の値が文字列
そのものではなく、`{ contains: ... }` というオブジェクトになる点に注意
(Prismaの「フィルタ条件オブジェクト」の書き方)。

### tier3
```ts
return prisma.book.findMany({ where: { title: { contains: keyword } } });
```

## listBooksSortedByRating

### tier1
並び替えはex01のlistAllBooksで使ったのと同じオプションキーを使う。
対象フィールドと向きを変えるだけ。

### tier2
`orderBy: { rating: direction }` の形。`direction` はこの関数の引数
そのまま渡せる("asc" | "desc" という型なのでPrismaが受け付ける形と一致)。

### tier3
```ts
return prisma.book.findMany({ orderBy: { rating: direction } });
```

## paginateBooks

### tier1
「検索付き一覧」は4つの部品(絞り込み・並び替え・件数制限・開始位置・
総件数)を組み合わせるだけで、新しい概念は無い。総件数は絞り込み後の
件数を数える専用のメソッドで取る(一覧を全部取得して`.length`しない)。

### tier2
- `where` はkeywordがあるときだけ `{ title: { contains: keyword } }`、
  無ければ `{}`(三項演算子で組み立てられる)。
- `findMany` に `where` と `orderBy: { id: "asc" }` に加えて
  `take: pageSize`、`skip: (page - 1) * pageSize` を渡す。
  `skip` は「先頭から何件飛ばすか」で、`page` そのものではない。
- 件数は `prisma.book.count({ where })`(findManyと同じwhereを渡す)。
- 2つの非同期処理は `Promise.all` でまとめて待つと効率がよい
  (順番に await してもテストは通るが、実務では並行実行が定石)。

### tier3
```ts
const where: Prisma.BookWhereInput = keyword === undefined ? {} : { title: { contains: keyword } };
const [items, total] = await Promise.all([
  prisma.book.findMany({ where, orderBy: { id: "asc" }, take: pageSize, skip: (page - 1) * pageSize }),
  prisma.book.count({ where }),
]);
return { items, total };
```
