# ex01_create_read ヒント

## createBook

### tier1
生成されたPrismaClientには model 名(小文字始まり)のプロパティが生えており、
そこに「1件作る」ためのメソッドが1つある。渡すオプションのキーは
「作りたいデータそのもの」を表す1語。

### tier2
`prisma.book.create({ data: ... })` の形。この関数の引数 `input` を
そのまま `data` に渡せる(NewBookInputはPrismaが受け付ける形と一致している)。

### tier3
```ts
return prisma.book.create({ data: input });
```

## listAllBooks

### tier1
一覧取得のメソッドは、条件を何も渡さなければ全件を返す。並び順を指定する
オプションキーが1つある(C#のLINQの `OrderBy` に相当)。

### tier2
`prisma.book.findMany({ orderBy: ... })` の形。`orderBy` にはフィールド名を
キーにして `"asc"` か `"desc"` を値にしたオブジェクトを渡す。idの昇順にする。

### tier3
```ts
return prisma.book.findMany({ orderBy: { id: "asc" } });
```

## findBookById

### tier1
「一意なキーで1件だけ探す」専用のメソッドがある(findManyとは別物)。
見つからなければ自動でnullになる(例外にはならない)。

### tier2
`prisma.book.findUnique({ where: { id } })` の形。

### tier3
```ts
return prisma.book.findUnique({ where: { id } });
```

## updateBookRating

### tier1
更新系メソッドは「どの行を対象にするか」と「何を書き換えるか」を
別々のキーで渡す。C#のEF Coreで `entity.Rating = x; SaveChanges()` と
書くのとは違い、Prismaは対象の特定と変更内容を1回の呼び出しに詰め込む。

### tier2
`prisma.book.update({ where: ..., data: ... })` の形。`where` にはid、
`data` には書き換えたいフィールドだけを渡せばよい(他のフィールドは
そのまま残る)。

### tier3
```ts
return prisma.book.update({ where: { id }, data: { rating } });
```

## deleteBook

### tier1
削除系メソッドも「どの行か」を`where`で1つだけ受け取る。戻り値は
削除された行そのもの(消える前の中身が返ってくる)。

### tier2
`prisma.book.delete({ where: { id } })` の形。

### tier3
```ts
return prisma.book.delete({ where: { id } });
```
