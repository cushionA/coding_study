# ex04_capstone ヒント

## ingestBooksAtomically

### tier1
複数の書き込みを1つの単位にまとめるための専用メソッドがある
(名前に`$`が付く、PrismaClient直下のメソッド)。渡し方は2通りあるが、
「1件目の結果(自動採番されたid)を2件目以降で使いたい」ときは、
配列をまとめて渡す形ではなく、**コールバック関数**を渡す形を使う。
コールバックの中で例外が起きれば、Prismaが自動で全部なかったことにする
——「途中で失敗したら投げっぱなしでよい」と考えてよい。

### tier2
`prisma.$transaction(async (tx) => { ... })` の形。コールバックの引数
`tx` は普段の `prisma` と同じ形をした、トランザクション専用のクライアント
——普段 `prisma.book.create(...)` と書くところを `tx.book.create(...)`
に置き換えるだけでよい。

流れ:
1. `tx.ingestRun.create({ data: { source } })` で1件作り、戻り値の `id`
   を覚えておく。
2. `books` を `for...of` などでループし、1件ずつ `tx.book.create` を呼ぶ。
   `data` には元のbook情報に加えて `ingestRunId: <1で作ったid>` を含める。
   途中の1件が失敗すれば、そこで投げられた例外がそのままコールバックの
   外まで伝わり、`$transaction` 自体がその例外でrejectされる(自分で
   try/catchしてもみ消す必要はない)。
3. 最後に、紐づく本ごと取得し直して(`include: { books: true }`)、
   その結果を `return` する。この戻り値がそのまま `$transaction(...)`
   全体の戻り値になる。

「見つからなければ例外を投げる」`findUniqueOrThrow` を使うと、
「作ったはずなのに無い」という起こり得ないケースをnullチェックで
分岐する手間が省ける。

### tier3
```ts
return prisma.$transaction(async (tx) => {
  const run = await tx.ingestRun.create({ data: { source } });
  for (const book of books) {
    await tx.book.create({ data: { ...book, ingestRunId: run.id } });
  }
  return tx.ingestRun.findUniqueOrThrow({ where: { id: run.id }, include: { books: true } });
});
```
