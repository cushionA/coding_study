# ex02_zod_schema ヒント

## buildBookDtoSchema

### tier1
zodは「オブジェクトの形」を`z.object({ フィールド名: 型のスキーマ })`という
形でそのまま書く。C#のクラス定義に近い感覚で、フィールドごとに「これは数値」
「これは文字列」と宣言していけばよい。空文字を許さない文字列や、
nullも許す数値には、それぞれ専用の書き方がある。

### tier2
- 数値: `z.number()`
- 空文字を禁止する文字列: `z.string().min(1)`(`min(1)`は「最低1文字」の意味)
- nullも許す数値: `z.number().nullable()`
4つのフィールド(book_id, book_title, author_name, publish_year)を
このルールで`z.object({...})`に詰めて返す。

### tier3
```ts
return z.object({
  book_id: z.number(),
  book_title: z.string().min(1),
  author_name: z.string().min(1),
  publish_year: z.number().nullable(),
});
```

## parseBookDto

### tier1
zodのスキーマには「投げっぱなしで例外になる」parseと、「成功/失敗を
オブジェクトで返してくれる」safeParseの2種類がある。ここでは後者を使い、
その結果(successフラグを持つオブジェクト)をこの関数の戻り値の形
(`ParseResult<T>`)に詰め替える。

### tier2
`buildBookDtoSchema().safeParse(raw)` の戻り値は `{ success: true, data }`
か `{ success: false, error }` のどちらか。`if (result.success)`で分岐し、
成功時は `{ ok: true, data: result.data }`、失敗時は
`{ ok: false, error: result.error.message }` を返す。

### tier3
```ts
const result = buildBookDtoSchema().safeParse(raw);
if (result.success) {
  return { ok: true, data: result.data };
}
return { ok: false, error: result.error.message };
```

## parseBookDtoList

### tier1
「1件のスキーマ」から「その配列のスキーマ」を作る専用の関数がzodにはある。
配列用スキーマができれば、あとはparseBookDtoとまったく同じ手順
(safeParse→分岐→詰め替え)で書ける。

### tier2
`z.array(buildBookDtoSchema())` で配列用のスキーマを作り、`.safeParse(raw)`
を呼ぶ。分岐と戻り値の形はparseBookDtoと同じ。

### tier3
```ts
const result = z.array(buildBookDtoSchema()).safeParse(raw);
if (result.success) {
  return { ok: true, data: result.data };
}
return { ok: false, error: result.error.message };
```
