# ex01_parse_response ヒント

## toBook

### tier1
外部から来たDTO(snake_case)とアプリ内のBook(camelCase)は、対応する項目を
1つずつ詰め替えるだけの単純なオブジェクトリテラルで作れる。C#で言えば
AutoMapperの`CreateMap<Dto, Domain>()`が自動でやってくれることを手で書くイメージ。
文字列2つだけ、前後の空白を取り除く一手間が必要な点に注意。

### tier2
戻り値は `{ id: ..., title: ..., author: ..., publishYear: ... }` の形。
`title`と`author`は文字列の`.trim()`メソッド(前後の空白除去)を通す。
`publishYear`は`dto.publish_year`をそのまま代入するだけでよい。

### tier3
```ts
return {
  id: dto.book_id,
  title: dto.book_title.trim(),
  author: dto.author_name.trim(),
  publishYear: dto.publish_year,
};
```

## toBooks

### tier1
配列全体をループで回して1件ずつ変換する処理は、配列の標準メソッド1つで
書ける(C#のLINQ `Select`に相当)。すでに1件変換する関数があるので、それを
そのまま渡せる。

### tier2
`dtos.map(...)` の引数に `toBook` をそのまま渡せる(アロー関数で包む必要は
ない、関数を値として渡すだけでよい)。

### tier3
```ts
return dtos.map(toBook);
```

## booksByAuthor

### tier1
比較する前に「表記ゆれ」を揃える必要がある。author引数の前後の空白と
大文字小文字を、比較対象(books側のauthor)と同じルールで揃えてから
`filter`(LINQの`Where`に相当)で絞り込む。

### tier2
`author.trim().toLowerCase()` で検索キーを作る。`books.filter(b => ...)`
の中で `b.author.toLowerCase()` と検索キーを`===`で比較する。

### tier3
```ts
const target = author.trim().toLowerCase();
return books.filter((b) => b.author.toLowerCase() === target);
```
