# ex02_typed_fetch ヒント

## isSuccessResponse

### tier1
Response には、成功か失敗かをすでに判定してくれているプロパティが1つある。
C#の `HttpResponseMessage.IsSuccessStatusCode` に相当する。自分で
`status >= 200 && status <= 299` を書く必要はない。

### tier2
`response.ok` を読むだけでよい。真偽値がそのまま欲しい答え。

### tier3
```ts
return response.ok;
```

## getStatusCategory

### tier1
4つの範囲を上から順にチェックする、素直な条件分岐でよい。
C#の switch式や if の連鎖と同じ発想。

### tier2
`if (status >= 200 && status <= 299) return "success";` のような形を
4分類ぶん並べる。最後は `return "unknown";` で締める。

### tier3
```ts
if (status >= 200 && status <= 299) return "success";
if (status >= 400 && status <= 499) return "client-error";
if (status >= 500 && status <= 599) return "server-error";
return "unknown";
```

## fetchJson

### tier1
流れは3ステップ: ①fetchFnを呼んでResponseを受け取る(await必須) ②成功判定
③成功ならjsonを取り出す、失敗ならエラーを投げる。この関数は既に作った
`isSuccessResponse` を利用できる。

### tier2
`const response = await fetchFn(url);` の後、`isSuccessResponse(response)` が
false なら `throw new Error(...)` する(メッセージに `response.status` を
含めること)。true なら `await response.json()` を返す(戻り値の型は `T`
にキャストする形で `as T` を付ける)。

### tier3
```ts
const response = await fetchFn(url);
if (!isSuccessResponse(response)) {
  throw new Error(`... status: ${response.status}`);
}
return (await response.json()) as T;
```

## fetchBook

### tier1
この関数は `fetchJson` を1回呼ぶだけで書ける。url を組み立てて渡し、
型引数に `BookApiResponse` を指定するのを忘れないこと。

### tier2
`fetchJson<BookApiResponse>(fetchFn, url)` の形。url はテンプレートリテラル
`` `/api/books/${id}` `` で組み立てる。

### tier3
```ts
return fetchJson<BookApiResponse>(fetchFn, `/api/books/${id}`);
```
