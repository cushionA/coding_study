# unit04: 分類と評価

このユニットを終えると、分類モデルの学習・評価・交差検証を一人で書けるようになる。
unit03の回帰と対になる、機械学習のもう一つの基本形。

## なぜ学ぶか

実務の「予測」の多くは、金額のような連続値ではなく「迷惑メールか否か」「不正取引か」「解約する顧客か」「どの品種か」といった**カテゴリ(ラベル)を当てる分類**である。回帰と並んで機械学習の仕事の大半を占め、しかも scikit-learn では回帰と同じ `fit`/`predict` の形でそのまま書ける。さらに実務では「正解率95%」の裏で肝心のクラスを全く検出できていない、という罠が普通に起こる。混同行列で「どう間違えたか」を読み、交差検証で「その数字はたまたまではないか」を検証できて初めて、モデルの良し悪しを他人に説明できる。分類の学習・評価・検証はデータ分析職の必須スキルである。

## 概念: 回帰と分類の違い

- unit03の回帰は「連続値をどれだけ正確に当てたか」を MAE/RMSE のような**誤差の大きさ**で評価した。分類は「有限個のクラスのどれかを当てたか外したか」を **accuracy(正解率)** という二値の的中で評価する。C#で言えば `double` の近似誤差を測るか、`enum` の一致判定をするかの違い。
- `LogisticRegression` は名前に Regression とあるが分類器。線形回帰の出力をロジスティック関数で「クラスである確率」に変換してから、最も確率の高いクラスを予測値として返す。
- accuracyだけでは「どのクラスをどのクラスと間違えたか」が分からない。**混同行列(confusion matrix)** は正解ラベル×予測ラベルのクロス集計表で、対角線が的中、それ以外が取り違えを表す。
- **precision(適合率)** は「陽性と予測した中で実際に陽性だった割合」、**recall(再現率)** は「実際に陽性のうち陽性と予測できた割合」。C#のテストで言えば precision は「Passと報告したうち本当にPassだった割合」、recall は「本当にPassだったもののうち検出できた割合」に近い。
- `train_test_split` は1回だけデータを分けるので、分割の運に結果が左右される。**交差検証(cross validation)** はデータをK個に分け、K通りの分割で学習・評価を繰り返して平均を取ることで、より安定した性能評価ができる。
