# unit05: 堅牢化とCSV出力

このユニットを終えると、汚れた実データを正規化し、壊れたレコードを安全にスキップしながら、
list[dict]をCSVファイルとして出力できるようになる。取得→解析ができても、この仕上げ工程
なしでは実務で使えるスクレイパーにはならない。

## なぜ学ぶか

実サイトの値は「全角/半角空白の混在」「¥記号やカンマ付きの価格」「ページごとに違う日付表記」
「一部のセルが空」など必ず汚れている。これを無視してそのままCSVに書き出すと、Excelで開いた
とき価格が文字列扱いになったり、後続の集計処理が例外で止まったりする。ここでは値の正規化、
異常データへの防御的な例外処理、一時的な通信失敗を想定したリトライ、そして標準ライブラリでの
CSV出力という「地味だが実務の8割を占める仕上げ作業」を一通り身につける。

## 概念: PythonとC#の対応

- `csv.DictWriter` はC#の CsvHelper の `CsvWriter.WriteRecords` に近い。ヘッダ行の自動生成、
  フィールド順の固定、クォート処理をライブラリに任せられる。
- Pythonの `try/except` はC#の `try/catch` と同じ発想だが、`int.TryParse` のような
  「例外を投げない版」の標準APIが無いことが多いため、自分で `try/except` を包んでフォールバック
  値を返す関数を作ることが多い。
- リトライの指数バックオフ+ジッタは、C#で `Polly` ライブラリが提供する `WaitAndRetry` と
  同じ考え方。ここでは `Task.Delay` に相当する待機処理を関数として注入し、テストで実際に
  待たずに済むようにする。
