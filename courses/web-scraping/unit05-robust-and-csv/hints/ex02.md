# ex02_error_handling ヒント

## safe_int

### tier1
C#の `int.TryParse` は失敗しても例外を投げずboolを返すが、Pythonの `int()` は失敗すると
例外を投げる。「例外を投げる関数をtry/exceptで包んでフォールバック値にする」という変換が必要。

### tier2
`int(text)` を `try:` の中で呼び、`ValueError`(数値に解釈できない)と `TypeError`(Noneなど)を
`except` で捕まえて `default` を返す。

### tier3
```
try:
    return int(text)
except (TypeError, ValueError):
    return default
```

## extract_field

### tier1
「キーが存在しない」「値がNone」「値が空文字列」の3パターンをすべて同じ扱い(default)にする
必要がある。`dict.get` はキー無し/Noneの場合しか対応しないので、空文字列は別途チェックする。

### tier2
`record.get(key)` でまず値を取り出し(無ければNone)、その値が `None` または `""` と等しいかを
判定してdefaultを返す。

### tier3
```
value = record.get(key)
if value is None or value == "":
    return default
return value
```

## retry_with_backoff

### tier1
リトライは「試行→失敗したら待つ→また試行」のループ。回数を重ねるほど待ち時間を伸ばすのが
指数バックオフで、複数クライアントが同時にリトライして再度衝突するのを避けるためにランダムな
ジッタを足す。テストで本当に待たないために、待つ処理自体を関数として外から渡してもらう
(C#で `Task.Delay` をモックに差し替えるのと同じ発想)。

### tier2
`while` ループの中で `func()` を `try` する。例外を捕まえたら試行回数を数え、上限を超えたら
`raise` で再送出する。超えていなければ `base_delay * (2 ** 試行回数) + jitter_fn()` を計算して
`sleep_fn(delay)` を呼んでからループを継続する。

### tier3
```
attempt = 0
while True:
    try:
        return func()
    except Exception:
        attempt += 1
        if attempt > max_retries:
            raise
        delay = base_delay * (2 ** attempt) + jitter_fn()
        sleep_fn(delay)
```
