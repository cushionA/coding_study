## parse_blog_post

### tier1
4つの値はそれぞれ別の探し方が要る。タイトルとリンクはタグ1件のテキスト/属性、
著者と投稿日は1つのテキストの中に " / " と ": " で埋め込まれているので、
文字列分割(unit01の復習)と組み合わせる。

### tier2
`soup.find(class_="post-title")` と `soup.find(class_="post-link")` でそれぞれ
テキストと `href` 属性を取り出す。`post-meta` のテキストは `.split(" / ")` でまず
著者部分・日付部分に分け、それぞれをさらに `.split(": ", 1)` してラベルを取り除く。

### tier3
```
title = soup.find(class_="post-title").get_text()
meta_text = soup.find(class_="post-meta").get_text()
author_part, date_part = meta_text.split(" / ")
author = author_part.split(": ", 1)[1]
date = date_part.split(": ", 1)[1]
link = soup.find(class_="post-link")["href"]
return {"title": ..., "author": ..., "date": ..., "link": ...}
```

`floor.find_all("span", class_="seat-count")` でそのフロア内のみの座席数タグを集める。

`{フロアのid: 合計}` の辞書にまとめる。

## find_busiest_floor

### tier1
辞書から「値が最大のキー」を求める処理。ループで自前に最大値を追跡してもよいが、
Pythonの組み込み関数には「比較に使う値の取り出し方」を指定できるものがある。

### tier2
`max()` にイテラブル(この場合は辞書、これはキーの列として扱われる)と
`key=` 引数を渡すと、key関数の戻り値で比較して最大のものを返す。
辞書の `.get` メソッドをそのまま `key` に渡すと「キーに対応する値」で比較できる。

### tier3
```
return max(seat_counts, key=...)
```
