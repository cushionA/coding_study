# unit06: キャップストーン: エンドツーエンドのスクレイパー

このユニットを終えると、robots.txtを尊重しながら複数ページを巡回し、
一覧→詳細→整形→CSV出力までを1本のパイプラインとして書けるようになる。
unit01〜05で個別に学んだ部品を、実務のスクレイパーと同じ形に組み上げる回。

## なぜ学ぶか

実際のスクレイピング案件は「1ページ分のパース」では終わらない。商品一覧はページネーションで
分割され、欲しい情報は詳細ページにしかなく、途中の1件が壊れていても全体を止めずに続行し、
相手サーバーに負荷をかけないよう間隔を空け、最終的に営業や分析チームが使えるCSVを出す
——というのが「一人称でスクレイパーを任せられる」状態。このユニットはその一連の流れを
ローカルフィクスチャ(架空のコーヒー豆通販サイト「喫茶ポラリス」)で安全に練習する。

## 概念: オーケストレーター関数とC#のサービス層

- `run_pipeline`のような「全体の流れだけを書く関数」は、C#で言えば複数のサービスクラス
  (`RobotsChecker`・`LinkCollector`・`DetailFetcher`・`CsvWriter`)を順番に呼び出す
  アプリケーションサービス/ユースケースクラスに相当する。中身の詳細は知らなくてよく、
  「誰を・どの順で・何を渡して呼ぶか」だけに集中できる。
- レート制限は`time.sleep`を直接呼ぶのではなく`sleep_fn`という関数を引数で受け取る形にする。
  C#で言えば`Task.Delay`をインターフェース越しに呼ぶ(テスト時はモックに差し替える)のと同じ
  発想で、テストが実際に何秒も待たされずに済む。

## 進め方

一覧・詳細ページの取得には、本物の`requests.get`の代わりに`fetch(url)`という
「URLをファイル名に変換してdata/site/から読み込む」ローカルフェッチャを使う。
ネットワークには一切アクセスしない。

| ステップ | 内容 | 目安 |
|------|------|------|
| lesson.ipynb | 全体設計図(巡回・マナー層・パイプライン合成)を一緒に確認 | 15〜20分 |
| ex01_collect_links | 一覧ページのページネーションを辿って全リンクを集める | 15分 |
| ex02_fetch_details | 詳細ページを1件ずつ取得してフィールドを抜き出す | 10分 |
| ex03_pipeline_integrate | クレンジングして整形済み辞書に変換しCSVへ書き出す | 10分 |
| ex04_capstone | robots.txt確認〜CSV出力までを1本に統合(総仕上げ) | 20分 |

このユニットはボリュームがあるので**2セッションに分けてよい**(lesson+ex01〜02 / ex03〜04 が目安)。
まず `lesson.ipynb` を上から実行し、その後 `ex01_collect_links.py` の TODO を埋めて
`python -m pytest courses/web-scraping/unit06-capstone-scraper/tests/test_ex01.py -q`
が通れば次へ。詰まったら Claude に聞く(段階的にヒントをくれる)。
