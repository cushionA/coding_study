# ex03_rate_limit ヒント

## wait_if_needed

### tier1
「前回からどれだけ時間が経ったか」と「最低どれだけ間隔を空けるべきか」を比べ、足りない分だけ
待てばよい。十分に経過していれば何もしない。

### tier2
`now - last_called_at` で経過秒数が出る。`min_interval` からそれを引いた「不足分」が正なら
`sleep_func` にその値を渡して呼び、その値を返す。不足していなければ `0` を返す。

### tier3
```
elapsed = now - last_called_at
remaining = min_interval - elapsed
if remaining > 0:
    sleep_func(remaining)
    return remaining
return 0
```

## handle_rate_limit

### tier1
429以外は何もしなくてよい。429のときだけ、サーバーが指定した待ち時間を尊重する。ヘッダの値が
無い場合のフォールバックも用意されている。

### tier2
`response.status_code` を見て429かどうか判定する。429なら `response.headers.get("Retry-After", default_wait)` で待つ秒数を取り出し(文字列で来るので数値化が必要)、`sleep_func` に渡してから `True` を返す。429でなければ `False`。

### tier3
```
if response.status_code != 429:
    return False
wait_seconds = float(response.headers.get("Retry-After", default_wait))
sleep_func(wait_seconds)
return True
```

## fetch_all_with_delay

### tier1
最初の1件は待つ必要がない。2件目以降だけ、前回いつ呼んだかを覚えておいて `wait_if_needed` と
同じ考え方で間隔を空ける。「前回呼んだ時刻」は毎回更新していく必要がある。

### tier2
`last_called_at` を `None` で初期化し、ループの中で `None` でなければ `wait_if_needed` を呼ぶ。
`fetch_func(url)` の結果をリストに集め、呼び出し後に `clock_func()` で `last_called_at` を更新する。

### tier3
```
results = []
last_called_at = None
for url in urls:
    now = clock_func()
    if last_called_at is not None:
        wait_if_needed(now, last_called_at, min_interval, sleep_func)
    results.append(fetch_func(url))
    last_called_at = clock_func()
return results
```
