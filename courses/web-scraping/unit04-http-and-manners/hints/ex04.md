# ex04_capstone ヒント

## get_body_with_retry

### tier1
429だけが特別扱い。429以外は、成功しているかどうかをそのまま見ればよい。429のときは
「待ってからもう一度だけ取得し直す」という手順が必要で、これはex03で作ったパターンと同じ。

### tier2
`response.status_code == 429` なら `response.headers` からRetry-Afterを取り出して `sleep_func`
を呼び、`fetch_func()` を呼んで `response` を更新する(再取得は1回だけでよい)。
その後 `response.ok` を見て `text` か `None` を返す(ex01の `get_body_if_ok` と同じ形)。

### tier3
```
if response.status_code == 429:
    wait_seconds = float(response.headers.get("Retry-After", default_wait))
    sleep_func(wait_seconds)
    response = fetch_func()

if response.ok:
    return response.text
return None
```

## fetch_if_allowed

### tier1
robots.txtで許可されていなければ、そもそも取得を試みるべきではない(fetch_funcを呼ばない)。
許可されていれば、取得してからこのファイルの `get_body_with_retry` に処理を任せられる。

### tier2
まず `is_allowed(rp, user_agent, path)` で許可を確認し、`False` なら即 `None` を返す。
許可されていれば `fetch_func()` を呼んで最初の `response` を得て、それを
`get_body_with_retry` に渡した結果をそのまま返す。

### tier3
```
if not is_allowed(rp, user_agent, path):
    return None
response = fetch_func()
return get_body_with_retry(response, fetch_func, sleep_func)
```
