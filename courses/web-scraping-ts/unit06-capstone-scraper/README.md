# unit06: キャップストーン: エンドツーエンドのスクレイパー

このユニットを終えると、robots.txtを尊重しながら複数ページを巡回し、
一覧→詳細→整形→CSV出力までを1本のパイプラインとして書けるようになる。
unit01〜05で個別に学んだ部品を、実務のスクレイパーと同じ形に組み上げる回。

## なぜ学ぶか

実際のスクレイピング案件は「1ページ分のパース」では終わらない。商品一覧はページネーションで
分割され、欲しい情報は詳細ページにしかなく、途中の1件が壊れていても全体を止めずに続行し、
相手サーバーに負荷をかけないよう間隔を空け、最終的に営業や分析チームが使えるCSVを出す
——というのが「一人称でスクレイパーを任せられる」状態。このユニットはその一連の流れを
ローカルフィクスチャ(架空のコーヒー豆通販サイト「喫茶ポラリス」)で安全に練習する。

## 概念: オーケストレーター関数とC#のサービス層

- `runPipeline`のような「全体の流れだけを書く関数」は、C#で言えば複数のサービスクラス
  (`RobotsChecker`・`LinkCollector`・`DetailFetcher`・`CsvWriter`)を順番に呼び出す
  アプリケーションサービス/ユースケースクラスに相当する。中身の詳細は知らなくてよく、
  「誰を・どの順で・何を渡して呼ぶか」だけに集中できる。
- レート制限は`setTimeout`ベースの待機を直接呼ぶのではなく`sleepFn`という関数を引数で
  受け取る形にする。C#で言えば`Task.Delay`をインターフェース越しに呼ぶ(テスト時はモックに
  差し替える)のと同じ発想で、テストが実際に何秒も待たされずに済む。
- 一覧ページの取得・詳細ページの取得には、本物の`fetch(url)`の代わりに`fetchLocal(url)`という
  「URLをファイル名に変換して`data/site/`から読み込む」ローカルフェッチャを使う。
  ネットワークには一切アクセスしない。

## 課題

- **ex01_collect_links**: 一覧ページから商品リンクを集め、次ページの有無を判定し、
  ページが尽きるまで巡回してURLを1つの配列にまとめる。
- **ex02_fetch_details**: 詳細ページのHTMLから商品フィールド(名前・価格・産地・焙煎度・在庫・
  説明)を生テキストのまま抜き出し、複数URLをまとめて処理する。
- **ex03_pipeline_integrate**: 「ラベル: 値」形式の文字列や「1200円」形式の価格文字列を
  整形し、自前のCSVライタでファイルに書き出す。
- **ex04_capstone**: robots.txtパーサ・巡回・詳細取得・整形・CSV出力を1つの`runPipeline`に
  統合する。sleepは関数として注入するのでテストは一瞬で終わる。

## マイルストーン(全部チェックできたらユニット完了、コース修了)

- [ ] ページネーションを「次ページが無くなるまで」ループで辿れる
- [ ] 一覧ページと詳細ページを分けて取得し、結果を1つのデータ構造に統合できる
- [ ] robots.txtを自前パーサで解釈し、許可されないURLへのアクセスを避けられる
- [ ] レート制限(Crawl-delay)をsleep注入の形でテスト可能に保ちながら実装できる
