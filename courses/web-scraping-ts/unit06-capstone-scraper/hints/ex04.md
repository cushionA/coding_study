# ex04_capstone ヒント

このユニットはex01〜ex03の再実装なので、まずそれぞれの`hints/ex01.md`〜`ex03.md`を
見直すと大半は解ける。ここでは capstone 固有の3つの関数(`isAllowed`・
`collectAllItemLinks`・`fetchAndCleanAll`・`runPipeline`)に絞って書く。

## isAllowed

### tier1
robots.txtは「`User-agent: 名前`の行から次の`User-agent:`行の直前まで」が1つのブロックで、
各ブロックに複数の`Disallow: パス`行がぶら下がる。自分のUser-Agentに一致するブロックが
無ければ`*`ブロックを使う、という優先順位を意識する。

### tier2
行ごとに分割し、`User-agent:`行が出るたびに「新しいブロックの開始」として現在のブロックを
切り替える。`Disallow:`行は現在のブロックにパスを追加する。判定時は
`targetUrl`から`new URL(targetUrl).pathname`でパス部分だけを取り出し、該当ブロックの
Disallowのいずれかで前方一致(`.startsWith()`)すれば拒否。

### tier3
```ts

  const rules: RobotsRule[] = [];
  let current: RobotsRule | null = null;

// targetUrlのpathnameがdisallowsのいずれかで始まっていればfalseを返す
```

## collectAllItemLinks(capstone版)

### tier1
`hints/ex01.md`の`collectAllItemLinks`と同じループ構造だが、ページ送りのたびに
`sleepFn()`を1回呼ぶ点だけが違う。「次のページに進む直前」に呼ぶのか
「ページを取得した直後」に呼ぶのかで回数が変わるので、テストが期待する回数
(3ページ→2回)から逆算して呼び出し位置を決めること。

### tier2
最終ページ(次ページが無い)ではもうページ送りをしないので、sleepFnを呼ぶ必要が無い。
「次ページURLが取れた場合だけ」sleepFnを呼んでからループの次の周に進む、という条件分岐になる。

## fetchAndCleanAll

### tier1
「1件ずつ取得→整形→配列に追加」する点はex02の`fetchAllItemDetails`と同じだが、
(1) 例外が起きたら`onError`を呼んでその1件だけスキップする、(2) 1件処理するごとに
`sleepFn(crawlDelay)`を呼ぶ、という2つの振る舞いが追加される。

### tier2
`try { ... } catch (error) { if (onError) onError(url, error); }`で1件ずつ囲む。
idは配列のインデックス`i`を使って`i + 1`(1始まり)にする。`sleepFn`の呼び出しは
try/catchの外(catchされてスキップした場合でも呼ぶ)に置くと「取得の成否によらず
毎回レートを守る」という自然な挙動になる。

## runPipeline

### tier1
このユニットで作った関数群を「robots確認→巡回→取得整形→CSV出力」の順で
呼び出すだけのオーケストレーター。robots.txtで許可されない場合は巡回も取得も行わず、
空配列のままCSV出力(ヘッダのみ)する分岐が必要。

### tier2
`fetchLocal(BASE_URL + "robots.txt")`でrobots.txtを読み、`isAllowed`に
`USER_AGENT`と`startUrl`を渡して判定する。許可されていれば
`collectAllItemLinks`→`fetchAndCleanAll`→`writeCatalogCsv`の順に呼び、
許可されていなければ空配列に対して`writeCatalogCsv`だけ呼ぶ。
`collectAllItemLinks`が要求する`sleepFn`は引数なし、`fetchAndCleanAll`が要求する
`sleepFn`は`delaySeconds`を受け取る形なので、`runPipeline`の`sleepFn`をそのまま渡すか、
ラムダで包んで橋渡しする。
