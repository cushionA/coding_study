# ex03_rate_limit ヒント

## waitIfNeeded

### tier1
「前回からどれだけ時間が経ったか」と「最低どれだけ間隔を空けるべきか」を比べ、
足りない分だけ待てばよい。十分に経過していれば何もしない。この関数自体が
`async` なので、待つ処理は `await` してから結果を返す。

### tier2
`now - lastCalledAt` で経過秒数が出る。`minInterval` からそれを引いた「不足分」が
正なら `await sleepFunc(不足分)` し、その値を返す。不足していなければ `0` を返す。

### tier3
```ts
const elapsed = now - lastCalledAt;
const remaining = minInterval - elapsed;
if (remaining > 0) {
  await sleepFunc(remaining);
  return remaining;
}
return 0;
```

## handleRateLimit

### tier1
429以外は何もしなくてよい。429のときだけ、サーバーが指定した待ち時間を尊重する。
ヘッダの値が無い場合のフォールバックも用意されている。

### tier2
`response.status` が429かどうか判定する。429なら `response.headers.get("Retry-After")`
で待つ秒数を取り出す(`null` の場合は `defaultWait`、値がある場合は文字列なので
`Number()` で数値化)。`await sleepFunc(...)` してから `true` を返す。429でなければ `false`。

### tier3
```ts
if (response.status !== 429) return false;
const retryAfter = response.headers.get("Retry-After");
const waitSeconds = retryAfter !== null ? Number(retryAfter) : defaultWait;
await sleepFunc(waitSeconds);
return true;
```

## fetchAllWithDelay

### tier1
最初の1件は待つ必要がない。2件目以降だけ、前回いつ呼んだかを覚えておいて
`waitIfNeeded` と同じ考え方で間隔を空ける。「前回呼んだ時刻」は毎回更新していく必要がある。

### tier2
`lastCalledAt` を `null` で初期化し、ループの中で `null` でなければ
`await waitIfNeeded(...)` を呼ぶ。`await fetchFunc(url)` の結果を配列に集め、
呼び出し後に `clockFunc()` で `lastCalledAt` を更新する。

### tier3
```ts
const results: string[] = [];
let lastCalledAt: number | null = null;

for (const url of urls) {
  const now = clockFunc();
  if (lastCalledAt !== null) {
    await waitIfNeeded(now, lastCalledAt, minInterval, sleepFunc);
  }
  results.push(await fetchFunc(url));
  lastCalledAt = clockFunc();
}
return results;
```
