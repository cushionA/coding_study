# ex04_capstone ヒント

## getBodyWithRetry

### tier1
429だけが特別扱い。429以外は、成功しているかどうかをそのまま見ればよい。429の
ときは「待ってからもう一度だけ取得し直す」という手順が必要で、これはex03で
作ったパターンと同じ。responseは再取得後に更新される点に注意。

### tier2
`response.status === 429` なら `response.headers` からRetry-Afterを取り出して
`await sleepFunc(...)` し、`await fetchFunc()` を呼んで新しいresponseに置き換える
(再取得は1回だけでよい)。その後 `response.ok` を見て `await response.text()` か
`null` を返す(ex01の `getBodyIfOk` と同じ形)。

### tier3
```ts
let current = response;

if (current.status === 429) {
  const retryAfter = current.headers.get("Retry-After");
  const waitSeconds = retryAfter !== null ? Number(retryAfter) : defaultWait;
  await sleepFunc(waitSeconds);
  current = await fetchFunc();
}

if (current.ok) {
  return await current.text();
}
return null;
```

## fetchIfAllowed

### tier1
robots.txtで許可されていなければ、そもそも取得を試みるべきではない(fetchFuncを
呼ばない)。許可されていれば、取得してからこのファイルの `getBodyWithRetry` に
処理を任せられる。

### tier2
まず `isAllowed(rules, userAgent, path)` で許可を確認し、`false` なら即 `null` を
返す。許可されていれば `await fetchFunc()` を呼んで最初のresponseを得て、それを
`getBodyWithRetry` に渡した結果をそのまま返す。

### tier3
```ts
if (!isAllowed(rules, userAgent, path)) return null;
const response = await fetchFunc();
return await getBodyWithRetry(response, fetchFunc, sleepFunc);
```
