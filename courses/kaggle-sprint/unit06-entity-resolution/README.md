# unit06: 名寄せ / エンティティ解決

このユニットを終えると、複数ソースのレコードから候補ペアを絞り、文字列・ベクトル類似度で同一判定し、グループIDへまとめられる。

## なぜ学ぶか

同じ商品や会社が表記ゆれで複数行になると、集計の二重計上とCVリークが起きる。全ペア比較は件数の二乗で増えるため、実務ではblockingで候補を減らし、取りこぼしと計算量を測る。これはunit02で必要だったgroupキーを自分で作る工程でもある。

blockingはC#なら `Dictionary<string, List<int>>` へバケツ分けして各バケツ内だけで組合せを作る処理。編集距離は競プロで使う2次元DP、最終クラスタ化はUnion-Findと同じ道具が使える。
