## measured_stage

### tier1
中身は ex01 の `throughput` とまったく同じ測り方で、結果を辞書に詰めて返すだけ。
「他人のベンチマークではなく自分の環境で測る」を関数の形で固定するのが狙い。

### tier2
`time.perf_counter()` の差で経過秒を取り、`件数 ÷ 経過秒` を `items_per_sec` に入れる。
`items` は Series で渡ることもあるので `list(...)` にしてから件数を取ると安全。
返す辞書のキーは `name` / `accuracy` / `items_per_sec` の3つちょうど(余計なキーを足さない)。

### tier3
```python
items = list(items)
t0 = time.perf_counter()
for x in items:
    fn(x)
elapsed = ...
return {"name": name, "accuracy": float(accuracy), "items_per_sec": ...}
```

## add_review_cost

### tier1
lesson の概念②でやった「精度差 × 件数 × 確認単価」を、表の全行にいっぺんに適用する。
基準になるのは**その表の中で最も高い精度**であって、1.0 ではない。

### tier2
- 列同士・列と数値の演算は、NumPy の配列と同じくブロードキャストで全行に効く。
  `plan["accuracy"].max()` がスカラーなので `最大値 - plan["accuracy"]` で差の列が得られる。
- 新しい列は `out["列名"] = ...` で足せる。
- **引数の表を書き換えてはいけない**ので、先に `plan.copy()` で複製する。
  これを忘れると呼び出し側の表にも列が増える(C# で参照型を渡したときと同じ事故)。

### tier3
```python
out = plan.copy()
out["accuracy_gap"] = ... - out["accuracy"]
out["review_yen_per_day"] = ...
out["total_yen_per_day"] = ...
return out
```

## choose_stage

### tier1
「処理時間の上限で絞る」→「残った中で総費用が最小の行を選ぶ」の2段階。
ex02 の `pick_threshold` とまったく同じ形で、絞る条件と選ぶ基準が違うだけ。

### tier2
- 絞りは `plan[plan["seconds_per_day"] <= max_seconds_per_day]`。
- 空なら `raise ValueError("...")`。メッセージには
  「その時間内で処理できる段が無い」と分かる情報を入れる。
- 「総費用が最小の行の**名前**」が欲しいので、`min()`(値が返る)ではなく
  `idxmin()`(index が返る)を使う。index は段の名前なのでこれがそのまま答えになる。
  `idxmin()` は同額のとき先に現れた方を返すので、仕様どおりになる。

### tier3
```python
ok = plan[...]
if len(ok) == 0:
    raise ValueError(...)
return str(ok["total_yen_per_day"]....)     # 最小値ではなく、その行の index
```

## stage_report

### tier1
ここまでの3つを呼ぶだけ。新しいロジックは無い。
返すのは「判断の根拠(表)」と「結論(段名)」の2つ — 実務では結論だけ出しても通らない。

### tier2
`stage_plan` → `add_review_cost` → `choose_stage` の順に呼び、
`(表, 段名)` のタプルで返す。`choose_stage` に渡すのは **`add_review_cost` を通したあとの表**
(総費用の列が無いと選べない)。

### tier3
```python
plan = stage_plan(...)
plan = add_review_cost(...)
return plan, choose_stage(...)
```
