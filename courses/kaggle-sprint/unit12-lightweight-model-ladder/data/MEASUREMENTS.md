## 段2: 軽量教師あり分類(ハッシュ n-gram + 線形分類器 = fastText 相当)

データ: `unit05-text-classical-nlp/data/train.csv`(商品テキスト 4000件・6クラス)
条件: janome 分かち書き + 正規化 → `HashingVectorizer(n_features=2**18, ngram_range=(1,2),
alternate_sign=False, norm="l2")` → `SGDClassifier(loss="log_loss", alpha=1e-6, max_iter=30)`。
`train_test_split(test_size=0.2, random_state=0, stratify=y)`。

    精度            accuracy 0.9150 / macro-F1 0.9079
    学習時間        0.24 秒(3200件)
    推論            95,840 件/秒(前処理を除く)
    形態素解析      667 件/秒
    1万件あたり     前処理 15.0 秒 + 推論 0.10 秒

### ★この段の核心: モデルより前処理が150倍重い

推論 95,840 件/秒 に対して形態素解析は 667 件/秒。**モデルを速くしても全体は速くならない。**
効くのは前処理側(分かち書き結果のキャッシュ、並列化、より軽い分割器への変更)。
「どこが律速かを測ってから手を入れる」という実務の型がそのまま出る。

比較: Day5 の TF-IDF + LogisticRegression は accuracy 0.9395。
**重い手法との差は 0.0245 しかないのに、学習は 0.24 秒で済む。**
「まずこの段で足りないか」を最初に確かめる根拠になる。

## 段3 / 段4: bi-encoder と クロスエンコーダ

データ: `unit06-entity-resolution/data/records.csv`(1340件・600商品)
埋め込み: `vocab.csv` の sense_group ごとに中心ベクトル + ノイズ(seed 0, dim 48)。
クロスエンコーダ相当: ペア特徴(正規化編集距離 / Jaccard / 埋め込みコサイン /
共通接頭辞長 / 長さ差)+ LightGBM。**商品単位で train/test を分割**(グループリーク回避)。

    bi-encoder のベクトル化    20,187 件/秒(1件 0.050 ミリ秒)
    ペア特徴の計算             1ペア 0.170 ミリ秒(5,947 ペア/秒)

### 二段構えの効果

    段3(bi-encoder 上位10件)で候補生成
      候補 8,849 ペア / 正例 862 件 → 再現率 75.9% / 正例率 9.74%

    段3のみ(類似度の閾値 0.92)   precision 0.318  recall 0.614  F1 0.419
    段3 → 段4(リランク)          precision 0.805  recall 0.687  F1 0.741  (+0.322)

### ★この段の核心: コストの「形」が違う

    bi-encoder    : n件をベクトル化すれば、全ペアは行列積1回で評価できる
                    1340件 → 0.07秒 で 897,130 ペアすべてを評価
    クロスエンコーダ: ペアごとに推論が要る
                    897,130ペア × 0.170ms = 2.5分

**倍率 2,273倍。** だから段4は「段3で絞った上位だけ」にしか使えない。
実際、候補 8,849 件に絞れば **1.5秒**で済む(全ペアなら 2.5分 = 100倍)。

**同時に上限も決まる**: 段3の候補生成が再現率 75.9% なら、段4をどれだけ精密にしても
**取りこぼした 24.1% は戻ってこない**。安い段で recall を確保し、高い段で precision を
上げる、という役割分担になる。

## 段0 / 段5: 規則 と 系列ラベリング(NER)

データ: `unit12-lightweight-model-ladder/data/ner_*.csv`(商品タイトルからブランド・型番・色を抽出)
train 3200 / test 800。評価は**正規形の完全一致**(`Ｔ６８２４９` から `T682-49` を復元できるか)。
段0 は「最初に書いた1書式の正規表現 + NFKC + ハイフン復元 + ブランド辞書」。
段5 は「文字単位の BIO タグ + 文字クラス窓特徴 + ロジスティック回帰」。

    test の内訳: 完全未知ブランド 10.0% / train に無い型番書式 33.0%

                    型番:全体  既知書式   新書式 | ブランド:全体   既知    未知
    段0 規則          0.2963   0.4422   0.0000 |    0.8800  0.9778  0.0000
    段5 系列ラベリング  0.6350   0.9478   0.0000 |    0.7963  0.8847  0.0000

    速度: 規則 219,928 件/秒 / 系列ラベリング 1,186 件/秒(185倍)。学習 3.0 秒

### ★この段の核心: 対象の性質で答えが3通りに変わる

1. **型番(書式が増え続けるもの)→ 学習モデルが勝つ**
   既知書式で 0.9478 vs 0.4422。train に書式が2種類ある時点で、正規表現は
   自分が書いた1種類しか当たらないのに、タガーは両方を吸収する。
   スクレイピングではメーカーごとに書式が違い、増え続ける。**継ぎ足し続ける正規表現は
   いずれ破綻する**、という判断の根拠がここにある。

2. **ブランド(列挙できる集合)→ 辞書が勝つ**
   既知ブランドで 0.9778 vs 0.8847。しかも **185倍速い**。
   閉じた集合に対しては学習モデルを持ち出す理由がない。「常に上の段が良い」ではない。

3. **完全に新しい書式 → どちらも 0.0000**
   例が無ければ学習モデルも学べない。ここが段5の限界であり、
   「新しい教師データを作る」か「事前学習済みモデルの世界知識を借りる」かの分岐点。

### 設計時に踏んだ失敗(教材にも書くこと)

初版は train に型番書式を**1種類しか入れなかった**ため、規則も学習モデルも
新書式で等しく 0.0000 になり、比較が成立しなかった。
これは段階表の話ではなく**分布シフト**の話になってしまう。
「学習データに無いものは学習モデルにも学べない」という当たり前の事実を、
比較実験の設計時に見落とすと、こういう無意味な結果が出る。

## 使えなかったもの(実務でも同じ制約に当たる)

### fastText の Python バインディング

`fastText 0.9.3`(2026-08 時点で最新)は **numpy 2.x で `predict()` が動かない**。

    ValueError: Unable to avoid copy while creating an array as requested.

`FastText.py` 内で削除済みの `np.array(obj, copy=False)` を使っているため。
学習と `test()` は動くが `predict()` が例外になるので、推論に使えない。
教材では同じアーキテクチャ(ハッシュ化した単語n-gram + 線形分類器)を
scikit-learn で実装して代替する。**本番で fastText を採用する場合は numpy を 1.x に
固定するか、C++ 実装を直接叩く必要がある。**

### 事前学習済みモデルの取得

`download.pytorch.org` / `huggingface.co` はいずれも組織のエグレスポリシーで 403。
そのため文埋め込みは疑似埋め込み(sense_group ベース)で代替している。
**検索・リランクの仕組みと評価は本物で学べる**が、絶対的な精度は実モデルとは異なる。
