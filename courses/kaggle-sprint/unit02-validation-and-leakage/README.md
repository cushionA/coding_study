# unit02: 検証設計とリーク

このユニットを終えると、データの生成過程に合う交差検証を選び、OOF予測を組み、リークを数値で発見できるようになる。

## なぜ学ぶか

Kaggleでも実務でも、手元の検証が本番を再現しなければ改善の判断を誤る。同一商品の重複収集や未来データの混入は、モデルを強くしたように見せながら本番では再現しない。まず分割を監査できることが、特徴量やモデルを試す前提になる。

`KFold` などの splitter は、C# なら `IEnumerable<(int[] trainIdx, int[] validIdx)>` を返す実装に近い。同じインターフェースの実装を差し替えつつ、OOF配列へ検証予測を元の位置に書き戻す。
