## clean_train

### tier1
ex02 の `clean_data` でやった4ステップと中身は同じ。ここでは「各ステップの記録」は不要で、
掃除後の DataFrame だけを返せばよい分、書くこと自体は ex02 より少ない。

### tier2
順番を変えないこと: 重複除去(item_id を除いた列で) → price<=0 を除外 → price>1,000,000 を除外
→ views<0 を NaN に置換。最後のステップだけ「行の削除」ではなく「値の書き換え」なので `.loc` を使う。

### tier3
```python
feature_cols = [c for c in df.columns if c != "item_id"]

df = df[df["price"] > ...]
df = df[df["price"] <= ...]
df = df.copy()

```

## category_condition_median_predict

### tier1
これがこのユニットの山場。lesson・ex03 では「カテゴリ」という**1つの軸**の未知値をどう埋めるかを扱った。
ここでは「カテゴリ×状態」という**2つの軸の組**を使うので、未知の起こり方が2種類ある:
「その組み合わせ自体が学習データに無い」と「そもそもカテゴリ自体が学習データに無い」。
だから退避先も2段必要になる(組み合わせ → カテゴリ単体 → 全体、の3段)。

### tier2
学習側から3つの対応表を作る:
1. `train_part.groupby([category_col, condition_col])[target_col].median()` — (カテゴリ, 状態) の組がキーの Series
2. `train_part.groupby(category_col)[target_col].median()` — カテゴリだけがキーの Series
3. `train_part[target_col].median()` — スカラー1個

`target_df` を1行ずつ見て(`target_df.iterrows()` で行番号と行が取れる)、
まず1の Series の index に `(そのカテゴリ, その状態)` のタプルが含まれるか調べ、あれば採用。
無ければ2の Series の index にそのカテゴリが含まれるか調べ、あれば採用。
どちらも無ければ3を採用。予測値は `target_df` と同じ長さ・同じ順序の配列に詰めていく。

### tier3
```python
pair_median = train_part.groupby([category_col, condition_col])[target_col].median()
cat_median = train_part.groupby(category_col)[target_col].median()
overall_median = float(train_part[target_col].median())

preds = np.empty(len(target_df), dtype=float)
for i, (_, row) in enumerate(target_df.iterrows()):
    key = (row[category_col], row[condition_col])
    if key in pair_median.index:
        preds[i] = ...              # pair_median.loc[key]
    elif row[category_col] in cat_median.index:
        preds[i] = ...              # cat_median.loc[row[category_col]]
    else:
        preds[i] = ...              # overall_median
return preds
```

## validate_submission

### tier1
lesson の概念4・②で表にした5項目(行数・ID集合・列名と順序・欠損ゼロ・負値なし)を、
`bool` の条件式にしてそのまま順番にチェックしていくだけ。「関数が例外を投げる」のではなく
「問題点の文字列を集めて返す」設計であることに注意(空リストなら合格)。

### tier2
- 列名と順序: `list(sub.columns) == [id_col, pred_col]`
- 行数: `len(sub) == len(test_df)`
- ID集合: `set(sub[id_col]) == set(test_df[id_col])`
- 欠損: `sub[pred_col].isna().any()`
- 負値: `(sub[pred_col].dropna() < 0).any()`

それぞれ `if 条件が悪い: problems.append("説明文")` の形を5回繰り返す。

### tier3
```python
problems = []
if list(sub.columns) != [id_col, pred_col]:
    problems.append(...)
if len(sub) != len(test_df):
    problems.append(...)
if set(sub[id_col]) != set(test_df[id_col]):
    problems.append(...)
if sub[pred_col].isna().any():
    problems.append(...)
if (sub[pred_col].dropna() < 0).any():
    problems.append(...)
return problems
```

## run_capstone

### tier1
これまでの3つの関数(`clean_train` / `category_condition_median_predict` / `validate_submission`)
と、すでに完成品として渡されている `split_holdout` / `rmsle` を、正しい順番でつなぐだけ。
新しいロジックはほぼ無い。「順番」と「どのデータで学習し直すか」がポイント。

### tier2
1. `clean_train(train_df)` で掃除する。
2. `split_holdout(掃除後のtrain, valid_frac, random_state)` で学習側/検証側に分ける。
3. ベースライン1(全体中央値)は `np.full(len(検証側), 学習側の全体中央値)` で作れる。
4. ベースライン2は `category_condition_median_predict(学習側, 検証側)`。
5. どちらも `rmsle(検証側の正解, 予測)` で採点し、小さい方を選ぶ。
6. **ここが忘れやすい**: 選んだ方法は、検証で使った「学習側(の一部)」ではなく、
   掃除後の **train 全体** を使って中央値テーブルを作り直してから test を予測する
   (手元にある全データを使い切るのが最終予測のセオリー)。
7. `pd.DataFrame({"item_id": ..., "price": ...})` で提出用の表を作り、`validate_submission` に通す。
   問題があれば `raise ValueError(...)`。

### tier3
```python
train_clean = clean_train(train_df)
tr_part, va_part = split_holdout(train_clean, valid_frac=valid_frac, random_state=random_state)

overall_pred = np.full(len(va_part), float(tr_part["price"].median()))
score_overall = rmsle(va_part["price"].to_numpy(dtype=float), overall_pred)

cc_pred = category_condition_median_predict(tr_part, va_part)
score_cc = rmsle(va_part["price"].to_numpy(dtype=float), cc_pred)

if ...:   # score_cc の方が小さければ
    test_pred = category_condition_median_predict(train_clean, test_df)
else:
    test_pred = np.full(len(test_df), float(train_clean["price"].median()))

submission = pd.DataFrame({"item_id": ..., "price": ...})
problems = validate_submission(submission, test_df)
if problems:
    raise ValueError(...)
return submission
```
