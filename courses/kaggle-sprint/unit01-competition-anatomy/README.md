# unit01: コンペの解剖と最初の提出

このユニットを終えると、コンペのデータ一式(train / test / sample_submission)を渡されただけで
「何を予測するのか」「どう提出するのか」「どう採点されるのか」を自分の言葉で説明でき、
壊れた入力を見つけてから、フォーマット違反のない `submission.csv` を自力で作れるようになる。

## なぜ学ぶか: 最初の30分がその後の全てを決める

新しいコンペを開いた日、あるいは実務で「このデータで価格を予測して」と CSV 一式を渡された日、
最初にやるべきことはモデルを書くことではない。**課題の構造を確定させ、入力を疑うこと**だ。
上位陣がほぼ全員やっているのが「初日に、雑でいいから1本提出する」習慣で、これには3つの理由がある。
提出パイプラインが通ることの確認、比較対象となるベースラインの確保、そしてデータ理解の穴が
実際に提出物を作ろうとして初めて表面化すること。このユニットはこの型を体に入れる回になる。

## 概念の顔見せ: DataFrame とC#の対応

- `DataFrame` は「`List<匿名型>` に LINQ を生やして、列方向にも切れるようにしたもの」。
- `df[df["price"] > 0]` は `list.Where(x => x.Price > 0)`、`df["price"]` は `list.Select(x => x.Price)` に相当。
- 既習の `numpy-masking`(ブールマスク)がそのまま `df[条件]` に効く — 新しく覚えることは実は少ない。

```python
df.loc[df["category"] == "家電", ["category", "price"]]   # 行と列を同時に切る。代入するときも必ずこれ
```
